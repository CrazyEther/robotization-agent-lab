1. Назначение

Пользователь выбирает объект, задаёт геометрию, транспортные зоны, поток заданий и свойства оборудования. Сценарий компилируется в типизированную агентно-событийную модель. Одна временная шкала формирует 2D-воспроизведение, загрузки и экономические расчёты.

3. Физические и дискретно-событийные процессы

Агентные сущности: робот с состоянием занятости, зарядом и местоположением; грузовая единица с жизненным циклом; заказ; рабочий пост с очередью и ограниченной вместимостью; зарядная станция.

Навигация: граф видимости с расширенными препятствиями и консервативным радиусом отпечатка робота. Время движения считается по длинам сегментов с ускорением и торможением, а не по одному параметру скорости.

Трафик: резервирование временных интервалов занятого пространства и учёт ожиданий. Это упрощённая макромодель; динамическое препятствие или SLAM не моделируются.

Технологическая нагрузка: поступления по фиксированному расписанию либо пуассоновскому потоку, FCFS и ёмкость станков, фиксированные или логнормальные длительности, вероятность доработки и новые грузовые единицы после трансформирующих операций.

Энергия: Wh/м по фактическому пробегу; очередь к зарядному месту, длительность зарядки, остаточный заряд и задержка начала задания.

4. Формулы и доказуемость

λ = заданий / секунду
фиксированное поступление: Δt = 1/λ
случайное поступление:     Δt = -ln(U)/λ

throughputPerHour = completed / shiftHours
backlog          = created - completed
utilization      = busySeconds / (capacity × horizonSeconds)
P95 cycle        = 95-й перцентиль завершённых циклов

CAPEX = unitPrice × robotCount + installation + infrastructure + chargers
OPEX  = maintenanceAnnual + energyKwhPerShift × daysPerYear × tariff
TCO   = CAPEX + years × (OPEX + residualHumanCostAnnual)
ROI   = (netAnnualBenefit × years - CAPEX) / CAPEX × 100%
NPV   = -CAPEX + Σ (netAnnualBenefit / (1 + discountRate)^year)

При неопределённых затратах, невыполнении заявленной годовой нагрузки или недостаточной статистической уверенности ROI/NPV не выдаются за достоверный результат. Каждый прогон фиксирует scenarioHash и независимый seed. Изменение условий обнуляет предыдущий результат.

5. Интерфейсы API

GET /api/v1/agent/health — диагностика ядра и лимиты публичной площадки. POST /api/v1/agent/study — исследование, выходы run.metrics, run.trace.events, experiment.metrics и список ограничений. GET /api/v1/catalog — исходный источник 44 карточек. Подробный контракт — API Reference.

7. Статус и честные границы модели

Это работающий предпроектный прототип, не полный AnyLogic и не сертифицированный цифровой двойник. Не реализованы полноценные пешеходные потоки, взаимодействие с лифтами, физический захват, кинематические особенности каждого производителя, реконструкция CAD и калибровка по журналам предприятия.

Сопоставимость результата с реальным объектом требует фактических расстояний, производственных времён, паспортных данных точной модели, перечня ограничений и полевых измерений.
