# RIS Agent Studio — независимый проект агентного моделирования роботизации

**Рабочий прототип:** https://ris-agent-studio-2026.battle-walleye.workers.dev

Сервис сохраняет визуальный стиль исходного Robot Investment Studio, но разрабатывается **в отдельной папке и самостоятельном Git-проекте**. Вторая площадка не является перезаписью `CrazyEther/robotization-platform` или `CrazyEther/robot-market`.

## Быстрый запуск

Нужны Node.js **24+**, npm, Git. В корне:

```bash
npm ci
npm run dev
```

Интерфейс: http://127.0.0.1:5173. API: http://127.0.0.1:8787. Для воспроизводимой проверки:

```bash
npm run build
npm test
npm run typecheck
```

Развёртывание нового, **отдельного** Cloudflare Worker (нужна авторизация в своём аккаунте): `npx wrangler deploy`. Конфигурация: `wrangler.jsonc`; Worker `ris-agent-studio-2026`. Исходные домены и репозитории не используются в качестве цели деплоя.

## Что реализовано в новой студии

- Двухмерный план с фиксированными препятствиями, двумя логистическими зонами, редактируемыми операциями (1–5), вместимостью рабочих постов и маршрутами для выбранной модели робота.
- **Simulation Core**: агентные экземпляры роботов, объекты-грузы, очереди операций, транспортные заявки, движение, резервирование конфликтных участков, ограничение парка и зарядных станций.
- Детерминированный дискретно-событийный цикл, случайные поступления Пуассона, логнормальное время операций, вероятность доработки, MTBF/MTTR ресурсов в вычислительном ядре.
- Отдельный EventTrace: движение и положение роботов / грузов на плане выводятся из результата **того же** прогона, откуда получены KPI.
- Независимые прогоны, seed, доверительные интервалы среднего, загрузка постов, трафик, дистанция, энергия, P95 и остаток заданий.
- Отчёт по капитальным затратам, ежегодным затратам и ROI/NPV **только при доказанной сопоставимости годового объёма и расходов**.
- Сохранённый источник каталога `data/catalog.json` (44 карточки), три отраслевых паспорта из `CrazyEther/robot-market`, два приложения из пользовательских материалов по производителям Aethon и TLD с ссылками и без вымышленных цен.
- Публичные GET `/api/v1/agent/health` и POST `/api/v1/agent/study`; проверка схемы и ограничение вычислительного объёма.

Отправная точка процесса: «забрать груз → доставить на пост → выполнить операцию → забрать новый груз или продолжить перевозку → сдать на выгрузку». Для больницы и аэропорта опубликованы только транспортные **демонстрационные** сценарии; помощь пациентам, санитарный режим и аэродромный допуск не моделируются.

## Что не следует считать реализованным

Это не полная копия AnyLogic или Gazebo и не сертифицированный цифровой двойник. Не реализованы SLAM, полноценное пешеходное движение, мультиэтажная логистика с лифтами, физический захват паллет, достоверная 3D-кинематика, полноценная предметная модель ухода за пациентами, WMS/MES/WCS интеграции и калибровка по эксплуатационным логам. Верификация модели и признание экономических результатов требуют данных конкретной площадки. Нельзя автоматически считать паспортный максимум скоростью на объекте или использовать стоимость робота из предложения «от» без учёта условий.

## Структура

```text
apps/web/Studio.tsx                существующий визуальный стиль / навигация
apps/web/AgentStudio.tsx           новая студия агента, трасса, финансовый блок
apps/api/app.ts                    публичный API / ограничение публичной нагрузки
packages/agent-studio/model.ts     компиляция отраслевого сценария в Process Graph
packages/simulation-core/         дискретные события, процессы, навигация, зарядка, трафик
packages/ris/                      старые контракты + воспроизведение EventTrace
data/catalog.json                  исходный справочник
data/market-scenarios/             3 паспорта из robot-market
data/market-supplement.json        2 строго атрибутированных дополнительных записи
docs/                              архитектура, API, ограничения, презентация
```

Запуск и источники не подразумевают гарантии точности для неоткалиброванного объекта.
